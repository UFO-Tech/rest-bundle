# ufo-tech/rest-bundle 1.x

Мажорна версія 1 відкриває методи JsonRpcBundle як REST API: атрибут Symfony `#[Route]` на RPC-процедурі робить метод доступним через HTTP з власним шляхом і HTTP-методом, а валідація, безпека, кеш і події лишаються в ядрі RPC. 1.0 додала адаптер, 1.1 — кілька входів для API-груп, 1.2 — Symfony 8, 1.3 переходить на JsonRpcBundle 10.4 (core executor, імпорт маршрутів для адаптерів, перекладена документація).

## Версії

| Версія | Головне |
| --- | --- |
| [1.0](1.0/README-UA.md) | REST-маршрути з `#[Route]` на RPC-процедурах; один вхід `/rest`; OpenAPI 3.1 (`GET /rest`) і Postman (`GET /rest/postman`); помилки RFC 9457; версії API під `/v2/...` |
| [1.1](1.1/README-UA.md) | Окремий REST-вхід для кожної API-групи (`defaults: { api_group: ... }`), імена маршрутів із префіксом групи та старі аліаси, документація і провайдери токенів для кожної групи, `405` замість `404` для неправильного HTTP-методу, `HEAD` для `GET`-маршрутів, суворий розбір JSON |
| [1.2](1.2/README-UA.md) | Symfony 8; Postman-колекція на базі core `AbstractPostmanAdapter`; `composer test` / `make test` |

## Нотатки з оновлення

- **1.0 → 1.1**: потрібні PHP 8.4 і JsonRpcBundle 10.2. Імена маршрутів отримують префікс групи (`general_ufo_rest_doc`); старі імена лишаються аліасами групи `general`. Неправильний HTTP-метод повертає `405` замість `404`. Некоректне JSON-тіло повертає `400`, а не ігнорується. Див. [1.1](1.1/README-UA.md#нотатки-з-оновлення).
- **1.1 → 1.2**: змін у коді застосунку не потрібно. Назва Postman-колекції змінилась на `REST: <project>`, з ` [group]` для груп, відмінних від типової.
- **1.2 → 1.3**: потрібен JsonRpcBundle 10.4.3; `RestYamlFileLoader` видалено; лістенери `rpc.post_response` тепер виконуються після REST-викликів. Див. [1.3](1.3/README-UA.md#нотатки-з-оновлення).
